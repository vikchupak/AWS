- [Official doc](https://docs.aws.amazon.com/AmazonS3/latest/userguide/example-bucket-policies.html)
- All s3 objects and buckets are private by default
- Have flat structure. Folders are just **emulated** with prefixes. S3 doesn't actually have folders
- Prefix means the part of an S3 object key that comes before the object name, conceptually similar to a folder path
  - `images/2026/08/` is a prefix for `images/2026/08/photo1.jpg`
  - one prefix can handle approximately:
    - 3,500 PUT/COPY/POST/DELETE requests/sec
    - 5,500 GET/HEAD requests/sec
- S3 maintains an index of object key names (in each AWS region). S3 stores key names in alphabetical order. The key name dictates which partition the key is stored in
- By default, an S3 object is owned by the AWS account that uploaded it even though the bucket is owned by another account. To get full access to the object, the object owner must explicitly grant the bucket owner access. You can create a bucket policy to require external users to grant `bucket-owner-full-control` when uploading objects so the bucket owner can have full access to the objects.

- **S3 Object Versioning**
  - Object versions are stored under the same key. Most fresh version is returned
    - You can get specific object version by providing object `Version ID`
  - Once enabled, it cannot be disabled, but suspended(paused)
  - `delete marker` is used to mark deleted objects. But object are not really deleted
- **Object Key Versioning**
  - Embedding version information directly in the object key (file name)
    - `images/v1/scan.png` -> `images/v2/scan.png`
    - `images/scan-v1.png` -> `images/scan-v2.png`
  - This is not a built-in AWS feature — it's a naming convention/pattern that developers use manually
- S3 performance optimization
  - **S3 multipart upload**
    - splits upload file on pieaces and sends them in parallel
  - **S3 transfer acceleration**
    - uses **CloudFront edge locations** and CloudFront Edge Network to send data faster
    - HTTP/HTTPS only as uses CloudFront

# Billing

You pay for all bandwidth into and out of Amazon S3, except for the following:
- Data transferred in from the Internet.
- Data transferred out to an Amazon EC2 instance, when the instance is in the same AWS Region as the S3 bucket (including to a different account in the same AWS region).
- Data transferred out to Amazon CloudFront.
